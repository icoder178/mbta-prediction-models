# Hyperparameter Tuning Guide

This document summarizes suggested hyperparameter tuning methods for the models used in `scripts/analysis_scripts/models.py`.

The project goal is model comparison, so tuning should use the same candidate budget and validation procedure for each tunable model where possible. The final test files should not be used to choose hyperparameters.

## General Tuning Protocol

Use the existing train/test split generated by `data_wrangling.py`.

Recommended workflow:

1. Build lagged train examples from the train CSV only.
2. Split the train examples chronologically into inner-train and validation, or use `TimeSeriesSplit`.
3. Run random search over a fixed number of candidates per model.
4. Select the best hyperparameters using validation RMSE.
5. Retrain the selected configuration on the full train examples.
6. Evaluate once on the held-out test examples.

Suggested search budget:

- Use `50` to `100` random candidates per tunable model for the main comparison.
- Use `1` candidate for `LinearRegression`, because it has no meaningful tuning parameters.
- Either leave `MovingAverage` as a baseline or tune only the global lookback window.

Sampling conventions:

- Use log-uniform sampling for scale parameters such as `alpha`, `C`, `gamma`, `learning_rate`, and `learning_rate_init`.
- Use integer random ranges for counts such as `n_estimators`, `max_iter`, and `n_neighbors`.
- Use categorical sampling for discrete choices such as `kernel`, `activation`, `weights`, and `max_features`.
- Keep `random_state=0` where supported so that comparisons are reproducible.

The scikit-learn defaults listed below reflect the current stable API documentation. The repo does not pin a scikit-learn version, so verify these against the installed package if the environment resolves an older version.

## Global Pipeline Hyperparameters

### Lookback Window

Current behavior:

- The pipeline uses `5` previous days of inputs to predict the next day.
- This value is passed as an argument to `models.py` and `test_model.py`.

Suggested tuning:

- If tuning globally, try values such as `3`, `5`, `7`, `14`, and `28`.
- Do not tune lookback independently for each model unless the comparison explicitly allows each model to choose its own temporal context.
- Larger windows increase feature dimensionality, especially for one-hot and weather feature sets.

Recommended status:

- Treat as a global experiment setting first.
- Keep fixed at `5` during the first round of model hyperparameter tuning.

### Feature Set

Current behavior:

- Each model is tested against multiple feature groups.
- `Best Added-Feature Set` means the best RMSE among the tested added-feature combinations.
- During tuning, choose this by validation RMSE and report final performance once on test RMSE.

Suggested tuning:

- For a clean comparison, use the same feature-set search policy for every model.
- Either tune hyperparameters separately for every feature set, or first select a feature set using default hyperparameters and then tune that model-feature-set pair.
- The first option is more exhaustive but much more expensive.
- The second option is cheaper but may miss interactions between model hyperparameters and feature representation.

Recommended status:

- Start by tuning each model on its default-best feature set and target-only baseline.
- Expand to all feature sets only if compute budget allows.

## RandomForestRegressor

### `n_estimators`

Meaning:

- Number of decision trees in the forest.
- scikit-learn default: `100`.

Tuning method:

- Sample integers on a moderate range, for example `100` to `1000`.
- More trees usually improve stability but increase runtime.
- Past a certain point, additional trees mostly reduce variance without changing bias.

Suggested distribution:

```python
randint(100, 1001)
```

### `max_depth`

Meaning:

- Maximum depth of each tree.
- scikit-learn default: `None`.

Tuning method:

- Use a categorical set including `None`.
- Smaller values regularize the trees and reduce overfitting.
- `None` allows full expansion and can work well with enough regularization elsewhere.

Suggested values:

```python
[None, 5, 10, 20, 40, 80]
```

### `min_samples_split`

Meaning:

- Minimum number of samples required to split an internal node.
- scikit-learn default: `2`.

Tuning method:

- Sample small-to-medium integers.
- Larger values regularize the trees.

Suggested distribution:

```python
randint(2, 51)
```

### `min_samples_leaf`

Meaning:

- Minimum number of samples required in each leaf.
- scikit-learn default: `1`.

Tuning method:

- This is often one of the most useful random forest regularizers.
- Sample integer values with more mass near small numbers.

Suggested distribution:

```python
randint(1, 31)
```

### `max_features`

Meaning:

- Number or fraction of features considered at each split.
- scikit-learn default: `1.0`.

Tuning method:

- Use categorical sampling over common values.
- Lower values increase randomness and reduce tree correlation.
- If `bootstrap=False`, keep values below `1.0` in the search space so that trees do not become nearly identical.

Suggested values:

```python
["sqrt", "log2", 0.3, 0.5, 0.8, 1.0]
```

### `bootstrap`

Meaning:

- Whether each tree trains on a bootstrap sample of rows.
- scikit-learn default: `True`.

Tuning method:

- Try both `True` and `False`.
- If `False`, tree diversity must come from `max_features`.

Suggested values:

```python
[True, False]
```

### `max_samples`

Meaning:

- Number or fraction of rows sampled for each tree when `bootstrap=True`.
- scikit-learn default: `None`.

Tuning method:

- Only valid when `bootstrap=True`.
- Use conditional search if supported, or omit this parameter in the first pass.

Suggested values:

```python
[0.5, 0.7, 0.9, None]
```

Recommended first pass:

- Tune `n_estimators`, `max_depth`, `min_samples_leaf`, `min_samples_split`, `max_features`, and `bootstrap`.
- Skip `max_samples` until conditional search logic is available.

## LinearRegression

### `fit_intercept`

Meaning:

- Whether to fit an intercept term.
- scikit-learn default: `True`.

Tuning method:

- Usually keep `True`.
- Because the data includes raw and scaled features depending on feature set, disabling the intercept is unlikely to be broadly beneficial.

Suggested values:

```python
[True]
```

### `positive`

Meaning:

- Whether to constrain coefficients to be nonnegative.
- scikit-learn default: `False`.

Tuning method:

- Usually keep `False`.
- Positive-only coefficients are hard to justify here because weather/calendar effects can plausibly be positive or negative.

Suggested values:

```python
[False]
```

Recommended status:

- Treat `LinearRegression` as an untuned baseline.

## Lasso

Meaning:

- L1 regularization strength.
- scikit-learn default: `1.0`.

Tuning method:

- Use log-uniform sampling.
- Higher values increase sparsity and can zero out features.
- Too high a value can collapse the model toward a constant predictor.

Suggested distribution:

```python
loguniform(1e-5, 1e3)
```

### `max_iter`

Tuning method:

Tuning method:

```python
[1e-4, 1e-3]
```

### `selection`

- Coordinate update strategy.
- scikit-learn default: `"cyclic"`.

Tuning method:

- Try `"cyclic"` and `"random"` if runtime allows.
- Keep `random_state=0` when using `"random"`.

Suggested values:

```python
["cyclic", "random"]
```

### `fit_intercept`

Meaning:

- Whether to fit an intercept term.
- scikit-learn default: `True`.

Tuning method:

- Usually keep `True`.

Suggested values:

```python
[True]
```

### `positive`

Meaning:

- Whether to force coefficients to be nonnegative.
- scikit-learn default: `False`.

Tuning method:

```python
[False]
```

## GradientBoostingRegressor

### `n_estimators`

Meaning:

- Number of boosting stages.
- scikit-learn default: `100`.

Tuning method:

- Sample integer values.
- Interacts strongly with `learning_rate`.
- More estimators can improve performance when paired with lower learning rates.

Suggested distribution:

```python
randint(50, 1001)
```

### `learning_rate`

Meaning:

- Shrinkage applied to each boosting stage.
- scikit-learn default: `0.1`.

Tuning method:

- Use log-uniform sampling.
- Lower values usually need more estimators.

Suggested distribution:

```python
loguniform(0.005, 0.2)
```

### `max_depth`

Meaning:

- Maximum depth of each individual regression tree.
- scikit-learn default: `3`.

Tuning method:

- Use small integer values.
- Gradient boosting often works well with shallow trees.

Suggested values:

```python
[1, 2, 3, 4, 5]
```

### `min_samples_split`

Meaning:

- Minimum samples required to split an internal node.
- scikit-learn default: `2`.

Tuning method:

- Sample integers to regularize tree complexity.

Suggested distribution:

```python
randint(2, 51)
```

### `min_samples_leaf`

Meaning:

- Minimum samples required in each leaf.
- scikit-learn default: `1`.

Tuning method:

- Important regularizer.
- Larger values smooth predictions.

Suggested distribution:

```python
randint(1, 31)
```

### `subsample`

Meaning:

- Fraction of rows used to fit each base learner.
- scikit-learn default: `1.0`.

Tuning method:

- Try values below `1.0` for stochastic gradient boosting.
- Can reduce overfitting.

Suggested values:

```python
[0.5, 0.7, 0.85, 1.0]
```

### `max_features`

Meaning:

- Number or fraction of features considered at each split.
- scikit-learn default: `None`.

Tuning method:

- Try categorical values.
- Smaller values add randomness and regularization.

Suggested values:

```python
[None, "sqrt", "log2", 0.5, 0.8]
```

### `loss`

Meaning:

- Loss function optimized by boosting.
- scikit-learn default: `"squared_error"`.

Tuning method:

- Start with `"squared_error"` for RMSE optimization.
- Try `"huber"` if outliers appear important.

Suggested values:

```python
["squared_error", "huber"]
```

Recommended first pass:

- Tune `n_estimators`, `learning_rate`, `max_depth`, `min_samples_leaf`, `subsample`, and `max_features`.
- Keep `loss="squared_error"` unless residual plots show strong outliers.

## Support Vector Regressor

### `kernel`

Meaning:

- Kernel function used by SVR.
- scikit-learn default: `"rbf"`.

Tuning method:

- Try `"rbf"` and `"linear"` first.
- Add `"poly"` only if runtime is acceptable.

Suggested values:

```python
["rbf", "linear", "poly"]
```

### `C`

Meaning:

- Regularization strength.
- scikit-learn default: `1.0`.

Tuning method:

- Use log-uniform sampling.
- Larger values penalize errors more and can overfit.

Suggested distribution:

```python
loguniform(1e-2, 1e3)
```

### `epsilon`

Meaning:

- Width of the epsilon-insensitive tube.
- scikit-learn default: `0.1`.

Tuning method:

- Use log-uniform or categorical values.
- Larger values ignore small errors and can smooth predictions.
- Because targets have very different scales for delay and GSE, consider task-specific ranges if tuning manually.

Suggested distribution:

```python
loguniform(1e-2, 1e2)
```

### `gamma`

Meaning:

- Kernel coefficient for `"rbf"`, `"poly"`, and `"sigmoid"`.
- scikit-learn default: `"scale"`.

Tuning method:

- Use `"scale"` and `"auto"` plus optional numeric log-uniform values.
- Only relevant for non-linear kernels.

Suggested values:

```python
["scale", "auto"]
```

Optional numeric distribution:

```python
loguniform(1e-5, 1e0)
```

### `degree`

Meaning:

- Polynomial degree for `kernel="poly"`.
- scikit-learn default: `3`.

Tuning method:

- Only relevant for polynomial kernels.
- Keep small to avoid extreme runtime and overfitting.

Suggested values:

```python
[2, 3, 4]
```

### `tol`

Meaning:

- Optimization tolerance.
- scikit-learn default: `1e-3`.

Tuning method:

- Usually keep default.
- Relax if runtime is too high.

Suggested values:

```python
[1e-3]
```

### `cache_size`

Meaning:

- Kernel cache size in MB.
- scikit-learn default: `200`.

Tuning method:

- Treat as a runtime parameter, not a model-quality hyperparameter.
- Increase if memory allows.

Suggested values:

```python
[500]
```

Recommended first pass:

- Tune `kernel`, `C`, `epsilon`, and `gamma`.
- Include `degree` only for polynomial candidates if conditional search is available.

## MLPRegressor

Meaning:

Tuning method:

- Use a small categorical set.

Meaning:

- Hidden-layer activation function.
- scikit-learn default: `"relu"`.

Tuning method:

- Try `"relu"` and `"tanh"`.
- `"relu"` is usually a strong default.
- `"tanh"` may work well with scaled features.

Suggested values:

```python
["relu", "tanh"]
```

### `solver`

Meaning:

- Optimization algorithm.
- scikit-learn default: `"adam"`.

Tuning method:

- Try `"adam"` first.
- Add `"lbfgs"` for smaller datasets if runtime is acceptable.
- `"sgd"` requires more learning-rate tuning and is usually a second-pass option.

Suggested values:

```python
["adam", "lbfgs"]
```

### `alpha`

Meaning:

- L2 regularization strength.
- scikit-learn default: `1e-4`.

Tuning method:

- Use log-uniform sampling.
- Important for controlling overfitting.

Suggested distribution:

```python
loguniform(1e-6, 1e-1)
```

### `learning_rate_init`

Meaning:

- Initial learning rate.
- scikit-learn default: `0.001`.

Tuning method:

- Use log-uniform sampling.
- Too high can diverge; too low can stall.
- Relevant mainly for `"adam"` and `"sgd"`.

Suggested distribution:

```python
loguniform(1e-5, 1e-2)
```

### `learning_rate`

Meaning:

- Learning-rate schedule for `"sgd"`.
- scikit-learn default: `"constant"`.

Tuning method:

- Only relevant for `solver="sgd"`.

Suggested values:

```python
["constant", "adaptive"]
```

### `batch_size`

Meaning:

- Minibatch size.
- scikit-learn default: `"auto"`.

Tuning method:

- Relevant for `"adam"` and `"sgd"`.
- Use categorical values.

Suggested values:

```python
["auto", 32, 64, 128]
```

### `max_iter`

Meaning:

- Maximum training iterations.
- scikit-learn default: `200`.

Tuning method:

- Set high enough for convergence.
- Do not treat as a primary predictive hyperparameter.

Suggested values:

```python
[500, 1000]
```

### `early_stopping`

Meaning:

- Whether to reserve part of the training data for internal early stopping.
- scikit-learn default: `False`.

Tuning method:

- Try both values carefully.
- With time series, sklearn's internal validation split is not time-aware, so external validation is usually preferable.

Suggested values:

```python
[False]
```

### `n_iter_no_change`

Meaning:

- Patience before stopping when improvement stalls.
- scikit-learn default: `10`.

Tuning method:

- Only relevant when early stopping or adaptive learning behavior is active.
- Keep fixed in the first pass.

Suggested values:

```python
[20]
```

### `tol`

Meaning:

- Optimization tolerance.
- scikit-learn default: `1e-4`.

Tuning method:

- Keep fixed unless convergence warnings are common.

Suggested values:

```python
[1e-4]
```

Recommended first pass:

- Tune `hidden_layer_sizes`, `activation`, `solver`, `alpha`, `learning_rate_init`, and `batch_size`.
- Keep `early_stopping=False` and use the project-level validation split instead.
- Set `max_iter` high enough to reduce convergence failures.


### `metric`

- Distance metric.
- scikit-learn default: `"minkowski"`.

- Keep `"minkowski"` when tuning `p`.

Suggested values:

```python
["minkowski"]
```

### `algorithm`

Meaning:

- Neighbor search algorithm.
- scikit-learn default: `"auto"`.

Tuning method:

- Usually keep `"auto"`.
- This is mostly a runtime parameter.

Suggested values:

```python
["auto"]
```

### `leaf_size`

Meaning:

- Leaf size for tree-based neighbor search.
- scikit-learn default: `30`.

Tuning method:

- Treat as a runtime parameter.

Suggested values:

```python
[30]
```

Recommended first pass:

- Tune `n_neighbors`, `weights`, and `p`.
